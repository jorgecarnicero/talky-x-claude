# v3.5 — v3 + high-precision passes (LIVE 91.92)

**Idea:** keep v3 as the backbone and let more precise, specialised passes answer first; v3's answers are then
imported into the *same open-item ledger* (no item settled twice), and a new AR matcher fills the receipts v3 left as
`UNIDENTIFIED`.

```
batches -> remittance -> ap_match -> nonitem -> v3import -> ar_match -> v3rest
```

| Pass (src/passes/) | What | Precision on its claims |
|---|---|---|
| batches | DD batches, card settlements, cheque deposits, payment runs (transfers/aggregated/confirming), returns, chargebacks; every lookup scoped to the bank account (run/batch ids repeat across entities) | 99.8 % |
| remittance | advices (pdf/csv/xlsx/txt) incl. the Sep-2025 XLSX layout (voucher/invoice/PO/net), credit notes netted, disputes | 99.98 % pairs |
| ap_match | supplier direct debits, transfers quoting supplier invoice numbers, supplier refunds of credit notes / duplicates | 99.8 % |
| nonitem | categories for lines that settle no item (fees, cash pool, payroll, reversal pairs, advances, refunds) | 99.8 % |
| v3import | v3's lines with items (minus items an earlier pass already cleared) | — |
| ar_match | only receipts v3 gave up on: payer by IBAN/name, refs (suffix/prefix/PO), subset-sum over open items, PDF instalments/advances | 90 % (no forced UNIDENTIFIED matches) |
| v3rest | v3's answer for everything else | — |

PDF clauses (`src/docs_extract.py`, `src/pdfinfo.py`): instalments, retention, advance to deduct, "anula y sustituye",
service month, rappel offset/paid out, credit-note refund/offset, factoring, new IBAN — parsed from 100 % of PDFs.

## Validation (anti-overfitting)
- Passes were tuned on TRAIN 2024-07..12 only. Scored on v3's dev window 2025-04..05 (never used for tuning):
  v3 82.83 -> v3.5 **92.82** (committed code; an earlier run during development gave 92.49) (alloc F1 0.866->0.942, txn acc 0.872->0.957, exc F1 0.668->0.833).
- LIVE: **91.92** (gap 0.90 vs the committed code's 92.82; v3 gap 0.58) -> local and LIVE agree within one point.
- No customer/supplier names, ids or amounts hard-coded; all rules from POLICIES.md + masters/side files.
